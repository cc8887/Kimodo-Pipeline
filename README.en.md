# Kimodo ALS Pipeline

[English](README.en.md) | [简体中文](README.md)

Turn motion generated by NVIDIA Kimodo into ALS animation resources, then validate the production stages and the resources consumed by Godot.

## Overview

Kimodo generates source motion. This pipeline manages the dependency graph, ALS resource production, and validation.

| Stage | What it does |
| --- | --- |
| Generation and derivation | Generates source motions, poses, and derived resources from an action dependency graph |
| Target production | Retargets to ALS, performs bounded repairs, separates Root/Pelvis motion, and writes per-asset curves |
| File validation | Reads back final FBX files and checks receipts and resource manifests |
| Consumer validation | Imports resources into the Godot project, builds, and runs relevant checks |
| Visual inspection | Uses Motion Viewer to compare stages from the current production batch |

Motion Viewer helps inspect batches and intermediate results. Playback in the viewer does not mean quality gates passed and does not replace final skinning and runtime checks in Godot.

## Quick Start

Clone the repository into a directory of your choice:

```bash
git clone https://github.com/cc8887/Kimodo-Pipeline.git
cd Kimodo-Pipeline
```

Production requires a Kimodo environment, approved access to the gated Llama text encoder, original ALS reference data, and a configured Godot consumer project. These models and assets are not included in the checkout. Follow the [installation guide](docs/入门教程.md) to set up WSL2 and Kimodo. Install this package into the active Kimodo Python environment, then create your Git-ignored local configuration as described in the guide. The detailed, step-by-step installation guide is currently in Simplified Chinese:

```bash
python -m pip install -e .
```

After configuration, run these commands from the repository root in WSL Bash to inspect and produce the Run scope:

```bash
python -m tools.doctor --verify-reference
python tools/produce_als_resources.py inspect --scope run
python tools/produce_als_resources.py run --scope run --keep-going
```

`run` is a subset of the Run motions, not the complete non-prop release scope. Check the exit code and batch report gates to determine whether the selected scope is deliverable. The installation guide covers the full pipeline and other scopes.

### Motion Viewer

Start the viewer in a separate Windows PowerShell terminal:

```powershell
& .venv-win\Scripts\python.exe tools\start_motion_viewer.py --port 10016
```

Then open [http://127.0.0.1:10016/](http://127.0.0.1:10016/). Set up this Windows Python environment by following the installation guide. See “Start Motion Viewer after each production run” in that guide for the batch inspection workflow.

## Editing Prompts

Most action prompts are configured by production scope:

| Scope | Main files |
| --- | --- |
| Run | `tools/kimodo_pipeline/run_rules.json` |
| Crouch | `tools/kimodo_pipeline/crouch_rules.json` |
| Walk, directional gait, and default non-prop scope | `tools/kimodo_pipeline/directional_gait_rules.json`, `tools/kimodo_pipeline/non_prop_rules.json` |
| Air, Mantle, and some fixed branches | `tools/kimodo_pipeline/air.py`, `graph.py` |

For rule inheritance and a step-by-step prompt workflow, see the [prompt section of the installation guide](docs/入门教程.md#6-想改-prompt到哪里改). Inspect `params.prompt` in the generated `graph.json` to confirm the effective prompt.
