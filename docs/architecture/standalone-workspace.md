# 独立生产目录与消费者边界

生产源码位于独立 Git 仓库。`paths.py` 读取 local TOML；相对路径以工具仓库为基准，所有路径支持 Windows 或 WSL 对应格式。生成后端与消费者是两个显式依赖。

## 原始参考

`reference_snapshot.py` 从当前 Godot 项目的原始 `assets/config`、`assets/generated/als_v4`、逐资产合同及两个 Stop 规则来源文件保存字节一致的快照，并记录 `reference.json`。活动包指针、compiled 和 import 缓存不进入参考快照。源规则指纹只作为消费者语义来源证据，不把 Core 算法复制到生产运行逻辑。

原始导出被项目 Git 忽略；仅有源码检出不能完成生产。快照也忽略入此 Git。迁移后，制作、转换和 FBX 回读读取快照，不要求访问消费者的原始资产目录；实际 Godot 验收仍需要消费者工程和相应消费能力。

## 两种清单

制作目录保留现有 `resource-pack.json` 格式用于兼容 Godot，它的 `res://` URI 相对于明确的资产根目录解析。新增 `bundle.json` 列出包内相对载荷路径、文件哈希、兼容清单哈希、参考版本、缺失和 FBX 回读结果。现有原采样时间、骨名、曲线与原生对照门限保持。

Godot 适配器把通过载荷检查的包复制到消费者的同名新版本目录。包内相对布局一致，所以不需要改写资源 URI。WSL 制作时，上游 retarget 元数据中的 Linux 绝对证据路径在部署副本里适配为 Windows 路径，另存 `deployment/retarget-bundle.json` 并登记其哈希；动画、raw 和曲线载荷不被这项适配重写。部署回执分别记录生产和消费两侧的兼容清单哈希。六域请求最终绑定也会更新部署副本中的配置及清单哈希，运行结果绑定这份实际副本，制作原包保持原字节。两份清单不是发布证书。

历史 `--base-pack` 可以显式引用原工程已有包：从包的位置推导 URI 根目录，重新检查全部载荷和上游作者回执，保留其已交付来源。这些旧回执仍含原始绝对路径；Windows 作者历史在 Windows 后端续作，WSL 后端复用自己的制作原包。旧批次尚不是跨系统、跨电脑自包含的作者历史归档。

## 完整执行

`run` 默认调用同一作者 DAG、成功分支转换和原质量门禁；没有有效交付时继续保留 source-quality 阻断证据。目标、FBX 或运行失败纳入 rejected 结果，不通过本次目录迁移改善资产资格。生产不会自动切换项目默认包。

`godot_adapter.py` 保留原来构建、导入、六域绑定和 E2E/Air/Mantle 检查。`runtime_bridge.py` 在 Windows Python 中运行消费者接口；WSL 调度仅在此边界用 `wslpath` 转换共享文件、Godot 和 dotnet 路径，避免把 Linux 路径直接交给 Windows Godot。跨系统配置入口与参考/项目根目录用显式参数传入。

Godot 项目的 Core、Import、运行场景和物理测试仍由消费者维护。已有项目命令继续工作；原生产目录保留迁移来源，不作为新目录的隐式算法依赖。

## Viewer

启动脚本分别挂载：消费者资产、独立生产资产、独立导出的作者预览。`/production-file/` 只读取生产根下的 FBX；`/authoring-file/` 只读取登记的预览；活动包仍读取实际消费者指针。路径边界与批次来源检查保留，缺失阶段保持缺失。Viewer 为人工检查工具，不能替代最终蒙皮、原生对照和游戏场景验收。
