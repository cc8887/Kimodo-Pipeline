# Kimodo 独立蹲走生产

`tools/produce_als_resources.py run --scope crouch` 默认使用 `crouch_rules.json`，选择前进、后退、纯左移、纯右移四种蹲走循环，共六个 V4／Refactored 身份。Refactored 没有纯侧移身份；四个斜向蹲走、参考姿态及蹲站过渡不在本范围内，组合包通过 `--base-pack` 保留已有交付。

源制作复用公共生成、原版姿态条件、周期修复、镜像和交付节点。前／后方向使用相应原版 Refactored 蹲走作生成条件；纯左移缺少同名 Refactored 原版来源，默认使用生成发现候选，右侧从通过检查的左侧母动作镜像。原版参考只用于约束，不能成为 Kimodo 交付。显式 `--upstream-receipts` 可以复用带身份、字节摘要、rig、时间域和通过源检查的左右母动作；无需再次推理。

`gaitMirrorSources` 可显式选择同时间域的左右母动作，例如从已有右侧母动作重新镜像左侧；两侧不能相互依赖，也不能跨语义映射。通过检查的镜像循环可复用于同名周期母动作，仍核对实际 gate／轨迹、数组摘要、rig 和帧数。镜像结果必须重新检测实际支撑事件，不能将原回执改名交付。

`gaitClosure.<semantic>.fullBodyPhaseFractions` 可细化生成阶段的周期姿态条件，默认四分相位；`fullBodyPhaseCycles` 与边界上下文共同计入每类型少于 20 帧的预算。超出预算在推理前失败，不增加条件上限。更密的条件是候选实验，不能据配置本身宣称动作改善。

前／后蹲走使用已验证的两周期八分相位配置，并开启 `gaitClosure.<semantic>.preserveReferenceHeading`。这保留参考动作骨盆自身的朝向及周期摆动；移动路径仍独立遵循目标方向和速度。密集 `root2d.global_root_heading` 使用同相位的实际髋线朝向，所有稀疏姿态／手脚条件仍通过原有朝向一致性检查。不得在保持直线路径的同时逐帧强制转正整个身体，否则会破坏原有支撑脚的世界轨迹。此选项默认关闭，不自动改变其他步态分支；参考须已由上游映射到目标移动方向。

保留朝向只能避免条件制作引入的滑步，生成结果仍须经过有界周期拟合、世界支撑锚点和固定骨长 IK，然后执行原有独立源／目标／运行门禁。不得用支撑阶段的近零脚速代替摆动、接缝、蒙皮或实际游戏验收。

`gaitClosure.<semantic>.targetPhaseHarmonics` 可按语义指定目标足底竖直相位的平滑阶数，必须为正整数且不超过周期采样带宽；未指定保持原三阶。后退蹲走采用已实测的二阶，避免平坦支撑区的小波动使低点选偏。该配置随交付合同传入已有目标修复，不改变交替相位要求、8 cm 目标脚部／5 cm 骨盆修正界限或最终质量断言，也不在失败时自动切换阶数。

目标检查通过 `target_gait.py` 复用公共 FK、时间域、Root、支撑、滑移、穿地和交替事件门禁。前／后蹲走使用对应 Refactored 原版几何；纯侧蹲走使用 `v4_recovery_movement_source_inputs.json` 和其校验摘要的原始骨骼轨道。V4 原始轨道不包含 Refactored 的 FootPlanted／同步标记，不伪造这类原版元数据。纯侧蹲走以原生前脚掌落地事件测时，仍要求脚跟和前脚掌同时通过平足支撑与速度检查；公共阈值保持。

默认执行完整转换、Root/Pelvis 分解、逐资产曲线、最终 FBX 回读、Godot 导入和运行。源失败不阻断独立通过资产的转换，失败／缺失清单保留。`--runtime-case` 可指定相关运行场景，省略则执行完整矩阵；相关检查不能代替完整生产验收，活动指针不自动切换。
